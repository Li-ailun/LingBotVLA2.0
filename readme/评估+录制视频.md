第20步请求新 chunk，继续执行旧动作5步，第25步切换；新 chunk 前15步受 RTC 引导，其中前5步因延迟被裁掉，剩余10步与旧 chunk 第25～34步做10步交叉淡化，最后对实际发布动作施加 α=0.36 的 EMA。

旧 chunk：
old[0:20]       old[20:25]       old[25:35]       old[35:50]
正常执行        推理期间执行       交叉淡化对象       不再使用
      │
      └─ 第20步发起RTC请求
                         │
                         └─ 第25步切换

新 chunk：
new_raw[0:5]    new_raw[5:15]                    new_raw[15:50]
RTC约束         RTC约束                           无直接RTC约束
时间已过期       保留并参与交叉淡化                 新轨迹
切换时裁掉       共10步

融合：
old[25:35] ↔ new_raw[5:15]
             ↓
      10步SmoothStep交叉淡化
             ↓
          EMA α=0.36
             ↓
           实际执行







适配结构已完成，两个模型现在统一支持：

- RTC / 非 RTC
- BF16 / FP32
- 独立日志目录
- 精确断点续评
- 单任务录像
- 不修改、不复制原始权重

核心适配器是 [model_registry.sh](/home/lixiang/PROJECT/LingBotVLA2.0/evaluation/model_registry.sh)，完整指令见 [MODEL_ADAPTERS.md](/home/lixiang/PROJECT/LingBotVLA2.0/evaluation/MODEL_ADAPTERS.md)。

模型名称：

- `step2000`：`lingbot_action_step2000`
- `full5k`：`lingbot_full_5k_6_60`
- `bf16`：运行时以 BF16 加载
- `fp32`：保持 FP32 推理

新模型非 RTC：

```bash
cd /home/lixiang/PROJECT/LingBotVLA2.0

bash evaluation/lingbot_action_step2000/run_eval.sh \
  demo_clean \
  --model full5k \
  --precision bf16 \
  --episodes 50
```

新模型 RTC：

```bash
cd /home/lixiang/PROJECT/LingBotVLA2.0

bash myscripts/simulation_rtc_tools/scripts/run_rtc_fast_50x50.sh \
  --model full5k \
  --precision bf16 \
  --episodes 50 \
  --request-index 20 \
  --fixed-delay-steps 10 \
  --execution-horizon 20 \
  --crossfade-steps 10 \
  --ema-alpha 0.21
```

旧模型使用同样指令，只需改成：

```bash
--model step2000
```

FP32 则改成：

```bash
--precision fp32
```

结果自动隔离到：

```text
evaluation/lingbot_action_step2000/results/<模型>/<精度>/<setting>/
myscripts/simulation_rtc_tools/results/<模型>/<精度>/<setting>/
```

断点续评已支持：

```bash
--resume-run-dir /原运行目录 \
--resume-task place_object_stand \
--initial-episode-count 10 \
--initial-success-count 2 \
--start-seed 100011
```

验证结果：

- 非 RTC 测试：13/13 通过
- RTC 测试：53/53 通过
- Bash 语法检查通过
- Python 编译检查通过
- RTC preflight 通过
- 四种模型/精度组合的 dry-run 通过
- 未启动任何评测 episode
- 未修改模型权重

注意：FP32 接口已经支持，但 6B 模型在单张 RTX 3090 上可能显存不足；实际正式评测优先使用 BF16。

旧模型将 `--model full5k` 改成 `--model step2000`。FP32 将
`--precision bf16` 改成 `--precision fp32`。

新录像目录严格区分模型、精度、RTC 类型、场景、参数和任务：

```text
evaluation/video_comparison/<model>/<precision>/non_rtc/<setting>/<task>/<run>/
evaluation/video_comparison/<model>/<precision>/rtc/<setting>/<rtc_params>/<task>/<run>/
```

例如：

```text
evaluation/video_comparison/full5k/bf16/non_rtc/clean/click_alarmclock/
evaluation/video_comparison/full5k/bf16/rtc/clean/request_20-delay_10-switch_30-horizon_20-xfade_10-ema_0p21/click_alarmclock/
```

# 实机录制、转换与数据分析

本流程录制R1Pro双臂16D数据：

```text
[左臂7关节, 左夹爪, 右臂7关节, 右夹爪]
```

不录制腰部。相机为头部、左腕、右腕三路RGB，数据频率为15 Hz。

## 1. 三个子任务

三个子任务都从随机物体布局开始。任务只规定盘子、杯子最终从下到上的颜色顺序，并要求杯子堆最终位于盘子堆上；不限定左侧、右侧或中间区域，也不限定具体的中间操作路径。

```text
1：蓝、粉盘子；蓝、红、黄杯子
2：蓝、粉盘子；红、黄、蓝杯子
3：粉、蓝盘子；黄、蓝、红杯子
```

颜色顺序为最终从下到上的堆叠顺序，录制脚本保存对应的完整英文指令。

如果需要取消话题就绪、订阅匹配和时间戳监控，直接启动 rosbag 录制：

```bash
/usr/bin/python3 myscripts/16d/record_tools/record_r1pro_mcap_episode.py \
  --root "$PWD/datasets/r1pro_mcap_raw" \

```

`--direct-recording` 只取消录制前和录制中的话题/时间戳监控，不改变 11 个录制话题、16D 维度顺序、人员/子任务目录和 episode 编号。旧写法 `--enable-timestamp-monitor false` 仍然可用。

启动后先输入录制人员：

```text
li
liu
yu
xing
```

人员在本次程序运行期间固定。随后输入 `1`、`2` 或 `3` 选择子任务。

然后输入本次录制的起始 MCAP episode 序号：

```text
Start episode index [recommended: 125]:
```

直接按 `Enter` 使用建议序号，也可输入预留给该机器人/操作员的起始号。如果当前“人员+子任务”目录已有同号的 `episode_XXXXXX_*`，脚本会列出冲突目录并要求重新输入，不会覆盖。保存后序号自动加一；切换 `1/2/3` 子任务时会针对新目录重新询问起始序号。

录制操作：

- 待机时按 `Enter`：开始录制当前子任务。
- 录制中按 `Enter`：停止并保留当前episode。
- 录制中输入 `q`：停止并删除当前episode。
- 待机时输入 `1/2/3`：切换子任务。
- 待机时输入 `q`：退出程序。

```bash
  --root "$PWD/datasets/r1pro_mcap_raw" \
```


启动后按录制时的顺序输入操作
员 `li/liu/yu/xing`、任务 `1/2/3`和起始MCAP episode。三路画面为顶部、左腕和右腕相机，episode按原MCAP数字序号排序。

窗口快捷键：`Space/p` 暂停/继续，`n` 下一条，`b` 上一条，`r` 重播，`1/2/3` 切换 `0.5x/1x/2x`，`d` 移出坏数据，`q` 退出。

播放时按 `d` 会暂停并显示红色确认标志；再次按 `Enter` 才会将整个原始episode目录移出正式数据集，按 `Esc` 取消。移出的数据保存在：

```text
datasets/r1pro_mcap_raw/_deleted_episodes/<删除时间>/<操作员>/<子任务>/episode_*/
```

这不是永久删除。每次操作还会追加记录到 `datasets/r1pro_mcap_raw/_deleted_episodes/deletion_manifest.jsonl`，其中包含原路径和隔离路径，便于恢复。确认后回放列表会立即移除该episode并继续下一条；若删除的是最后一条，则回到上一条。

## 3. MCAP转换为16D中间格式

三个子任务一次性递归转换：

```bash
cd /home/lixiang/PROJECT/LingBotVLA2.0
source /opt/ros/humble/setup.bash

/usr/bin/python3 myscripts/16d/convert_tools/export_r1pro_mcap_to_intermediate.py \
  --input "$PWD/datasets/r1pro_mcap_raw/stack_plates_and_cups" \
  --output "$PWD/datasets/r1pro_intermediate_16d/stack_plates_and_cups" \
  --fps 15 \
  --max-image-dt 0.12 \
  --max-vec-dt 0.20 \
  --overwrite
```

中间格式保留相同的人员和子任务目录，并在`manifest.json`及`episode_meta.json`中记录原MCAP人员、episode序号和路径。

## 4. 构建LeRobot v2.1数据集

```bash
cd /home/lixiang/PROJECT/LingBotVLA2.0
export HF_LEROBOT_HOME="$PWD/datasets/lerobot"

/home/lixiang/PROJECT/openpi/.venv/bin/python \
  myscripts/16d/convert_tools/build_lerobot_from_r1pro_intermediate.py \
  --input "$PWD/datasets/r1pro_intermediate_16d/stack_plates_and_cups" \
  --repo-id lixiang/stack_plates_and_cups_16d \
  --fps 15 \
  --resume/overwrite \
  --episodes-per-worker 10
```

转换器每10个episode自动重启一次子进程，避免Arrow、Pillow和图像写入缓存长期累积导致OOM。进程意外中断后，保持intermediate内容和排序不变，可将`--overwrite`替换为`--resume`，从已经完整保存的下一个LeRobot episode继续。

输出目录：

```text
datasets/lerobot/lixiang/stack_plates_and_cups_16d/
```

每个episode会保留对应的完整英文语言指令。

LeRobot合并顺序固定为：每个子任务内按`li -> liu -> yu -> xing`排列，每个人内部按原MCAP episode序号排列；然后再进入下一个子任务。LeRobot保持标准零基连续编号：

```text
episode_000000
episode_000001
episode_000002
...
```

详细来源对应表位于：

```text
datasets/lerobot/lixiang/stack_plates_and_cups_16d/meta/episode_source_map.csv
datasets/lerobot/lixiang/stack_plates_and_cups_16d/meta/episode_source_map.jsonl
```

每条记录包含LeRobot编号、从1开始的查看序号、录制人员、子任务、原MCAP episode编号及目录、intermediate目录和帧数。

如果回放后发现坏数据，推荐直接在原始MCAP回放窗口按 `d`，再按 `Enter` 将其移入 `_deleted_episodes`。也可以手动处理：

1. 在`episode_source_map.csv`中查对应原MCAP；
2. 将该原MCAP episode目录移出正式任务目录；
3. 使用第3节带`--overwrite`的命令重建全部intermediate；
4. 使用第4节带`--overwrite`的命令重建LeRobot。

重建后LeRobot序号会重新连续排列，并生成新的准确映射。不能只删除MCAP而保留旧intermediate，否则旧数据仍会被转换。

```bash
cd /home/lixiang/PROJECT/LingBotVLA2.0

MPLCONFIGDIR=/tmp/matplotlib-r1pro16d \

  myscripts/16d/lerobot_tools/check_lerobot_v21_numeric_and_plot.py \
```

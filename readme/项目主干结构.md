# LingBotVLA2.0 项目主干结构

项目根目录：

```text
/home/lixiang/PROJECT/LingBotVLA2.0
```

本文用于向新的开发者或 AI 助手同步项目结构。它完整展开与训练、推理、RoboTwin 评估、RTC、视频和数据检查有关的主干；模型权重分片、数据帧、仿真 mesh/texture、运行日志和缓存只展开到有意义的目录层级。

## 二、当前正式工作链路

```text
模型权重
models/lingbot_action_step2000/
        │
        ├── 非 RTC
        │   evaluation/lingbot_action_step2000/policy_server.py
        │           ↓ WebSocket
        │   lingbot-vla-v2/experiment/robotwin/eval_policy_client_lingbotvla.py
        │           ↓
        │   RoboTwin_lingbot/
        │
        └── RTC
            myscripts/simulation_rtc_tools/server/policy_server_rtc.py
                    ↓ WebSocket + RTC protocol
            myscripts/simulation_rtc_tools/copied_eval/
              eval_policy_client_lingbotvla_rtc.py
                    ↓
            RoboTwin_lingbot/
```

两个评估分支共用官方 RoboTwin 任务、物理环境、成功判定和 step limit。RTC 分支只改变模型采样与 action chunk 的调度、裁剪、交叉淡化和 EMA，不应修改任务定义或成功判定。

## 十三、环境与迁移边界

本机使用两个主要 Conda 环境：

```text
lingbotvla   # 模型加载、训练和推理服务
RoboTwin     # SAPIEN、MPLib、CuRobo、PyTorch3D和仿真客户端
```

迁移服务器必须复制：

```text
lingbot-vla-v2/
RoboTwin_lingbot/
models/
evaluation/
myscripts/
readme/
```

训练时还必须复制：

```text
RoboTwin2_data/
```

只做推理评估时可不复制完整训练数据集。

不应作为源码迁移主体的内容：

```text
**/__pycache__/
**/.pytest_cache/
.venv_modelscope_download/
result/
历史 results/（除非需要续评或保留证据）
模型与数据下载缓存
```

需要特别检查的非便携内容：

```text
1. 脚本中的 /home/lixiang 绝对路径
2. CuRobo YAML 中指向本机 RoboTwin assets 的绝对路径
3. Conda editable-install 的 curobo .pth 路径
4. CUDA_HOME、编译器和 PyTorch CUDA 版本
5. SAPIEN headless/Vulkan/EGL 渲染能力
6. 多GPU时端口范围、CUDA_VISIBLE_DEVICES和每卡显存
```
